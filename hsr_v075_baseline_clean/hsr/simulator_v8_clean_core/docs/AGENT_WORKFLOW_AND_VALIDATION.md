# 本地执行与验证约定

## 0. 当前本地工作方式

目标是尽量还原实际战斗行为。保留 L0 来源编译、L1 通用执行、L2 内容装配、L3 外部操作，
以及原子提交、确定性 RNG、结算明细和 replay；不完整复刻原生引擎的内部组织。
当前任务与支持边界只在 [CODEX_HANDOFF.md](../../CODEX_HANDOFF.md) 维护。

2026-11-10 用户确认[方向矫正](../PROJECT_GOALS.md#2026-11-10-方向矫正)：终点改为 v1 名单；
专属行为可写内容卡的专属处理器；正确性以游戏数值对照衡量，来源审计降为可开关的调试能力；
性能是验收项。本文与之冲突的旧要求已按此修订。

2026-10-10 用户明确：成本应带来实际推进，不限制单次运行成本；按里程碑评估总收益。
工作按可用成果或可证明的维护收益组织，同根问题集中修复，不以单个 blocker、
文件拆分数量或测试数量作为交付。

2026-10-12 用户纠正：可靠攻略、数据网站及测试条件明确的成熟结论可直接用于实现；减少
重复查证和过量测试。下述来源与验证约定覆盖旧文档中 TBGD 唯一来源、逐机制负例矩阵和
每批必跑整场/独立回放的要求。最终产品范围不缩减。

## 事实、实现与范围

- 2026-11-13 用户授权适用于整个 v1：先读技能描述，用自己的话列行为清单；TBGD 仅取参数及
  回答具体疑问，过滤镜头、动画，不自上而下遍历能力图。时序和边界可采用最合理的解释，
  定义处记录条件、理由、待实测事项，实际结果显示“未实证”。数值、倍率和概率绝不猜，
  带假设可运行与已实证分开报告；后续交付持续提醒尚未完成的实测。
- 工作以 v1 名单条目为单位：每批说明完成了哪些条目的“可战斗”和“数值已对照”。名单外的缺口
  记一行已知限制，不立项；名单未确定时只做不依赖名单的地基工作。
- 先定位正式调用链与生产权威，优先复用现有机制、参数和装配入口；只补真实缺口。
- 普通接线与修复在已授权范围持续完成；不自动触发 MCP、固定执行角色、审批卡或逐卡 PR。
- 特殊机制由具体内容推动；旧阶段未勾选不等于没有实现，也不扩大当前任务范围。
- 未知规则、来源缺口、实现缺口、接线问题和未验证分别记录；数值未知只阻断实际依赖，
  时序和边界优先采用上述带标记解释推进。
- 先采用适用的 TBGD 数据或可靠攻略、数据网站和实测研究；PR #8 已确认结论继续有效。
  成熟结论无需重新逆向、亲自重做原实验、找到 TBGD 同值或逐条请用户批准。
- 在现有规则定义或机制缺口记录中简记资料链接、采用结论、适用版本/条件及已知例外即可；
  不新增证据平台、审批卡或每机制报告。一份充分说明条件的可靠资料即可，不强制多源互证。
  版本未注明时如实记录，只查影响当前内容的适用差异；不得伪造确定性。
- 资料一致且覆盖当前行为就实现；仅对实际冲突、缺失条件或不适用版本补查，优先核对原始
  测试/数据，不从头重做整套机制研究。同一缺口无新证据时不重复搜索，保留具体待答问题。
- 公式、参数和时序可人工整理后通过已有 IR/RuleBook 入口注册，注明实际来源，不伪称 TBGD
  来源，不要求开发网页导入器。时序和边界假设保留“未实证”标记，原生内部命名不作为采用前提。
- 游戏观察记录版本、构筑、目标、操作、时间戳与可见值，区分观察和解释；
  跳字数量不代表内部请求数，未知构筑的数值不能补公式。
- 新依赖、下载、扩大权限、创建或覆盖 uv 环境先询问；复用工作区已有环境。
- 公共接口或归档不兼容时先明确兼容要求。用户已在本轮明确不兼容旧规则指纹归档。
- 没有另行授权不提交、不推送、不创建 PR，不更新 TBGD submodule 指针。
- 手工编辑使用 apply_patch；临时数据写 /tmp，保留用户无关改动。

## 实施闭环

开发批次按共享机制及其实际依赖内容组织：

- 对已知玩法，优先将 TBGD 参数和已采纳资料整理为现有类型化规则，复用内核执行。
  不要求逐项复刻原生任务、动画同步或内部回调组织。
- 现有机制表达不了时按成本选路径：多个名单内容共用的行为扩展通用机制一次；只有一个内容
  使用的行为写该内容卡的专属处理器，边界见
  [架构契约](../ARCHITECTURE_BOUNDARY_CONTRACT.md#内容专属处理器)。不为单个内容改动
  lowering、IR 和多个 system；出现第二个使用者再提升为通用机制。
- 开工前估计两条路径各自要动的文件和行为面，交付时记录实际投入，供后续同类内容参考。
- 开工时读完本批行为的完整相关链，例如创建、使用、到期、销毁与再次创建；从已有 IR、
  来源和正式调用者集中找出可见缺口，按共同生产者/消费者归并。静态阻断、运行错误与
  尚未验证分别处理，不把全部 blocked 记录逐条变成开发任务。
- 同一根因集中修改，核对受影响的同类内容；单个角色样例用于发现和证明机制，不代替
  同族内容接入。批次交付说明新增可用范围及剩余依赖，不以测试数量衡量推进。
- 共享机制修复前，先沿完整相关链列清生产权威、传播与消费边界、不变量及必要验收
  场景，与实现任务一并给出；较长契约放对应任务说明，交接只保留状态和入口，不强制每次
  新建文档。复用或补齐对应检查。同根问题归入同一清单，整组通过后集中验收。
  验收先完整审查差异与调用者，再合并验证，集中反馈。
- 编译准入、运行执行、原子性和数值对照分别按实际证据报告，不相互代替。验收新发现的
  问题须给出复现与受影响行为；新增功能需求另列，不混作本批缺陷。
- 运行阻断先保存正式输入、命令与失败前状态，复用当前范围的规则定位；局部状态只用于
  组件诊断，不能冒充公开流程证据。先完成相关局部修复，再合并运行代表性整场，减少
  为发现下一个缺口反复从入场重跑。验证结果若暴露新问题，按下文验证选择处理。
- 首次得到有效路线或阶段前置时，一并保存原生归档和所需中间观察。后续仅核对事件、
  mutation、settlement 字段或前后快照，且没有影响该结果的新改动时，直接读取已有归档，
  不从入场重跑作字段定位。重审归档结算时核对所用 RuleBook 的规则指纹；这属于结果重审，
  不称为重新执行战斗或独立 replay。
- 调整外部操作路径时，优先复用现有 CLI 交互会话并保持进程，达到目标或明确阻断后保存退出。
  正式 `restore_session` 会完整重放校验；保存归档便于读证据，不等于免重放的快照恢复。

1. 明确本批可观察成果、受影响权威、调用者；只选择能发现本次实际错误的必要检查。
2. 形成最小完整改动；结构整理与规则变化分别实施，便于定位回归。
3. 运行受影响检查，集中修复同一根因。
4. 达到本批行为目标后停止验证并推进下一项，更新短交接与剩余限制，不以继续加测替代交付。

如果两轮修复同一根因仍无新进展，停止沿通用路径加码：改写专属处理器，或说明原因交用户裁决。
不通过增加验证器、扩大扫描或反复加载历史文档代替决策。复杂跨领域修改才补窄执行说明，
普通任务不强制新卡或报告。

## 验证选择

现行命令见 [tests/README.md](../tests/README.md)。默认选择最小相关检查，现有检查能覆盖就
不新增；非平凡逻辑保留一个能发现错误的可运行检查，简单可逆的一行修改无需专门建测试。
表中按实际影响选取，不逐行叠加成每次必跑套餐。

| 改动 | 必要证据 |
| --- | --- |
| 文档、导航 | 链接、事实一致性、diff |
| 名单条目接入或其数值规则变化 | 一条经公开操作的正式路线，加一组游戏数值对照；对照记录版本、构筑、目标、操作、对照值及其来源 |
| 单一规则、公式或来源形状 | 一个相关行为检查，可直接复用现有测试；不另加同义正例或负例矩阵 |
| 来源范围、引用关系 | 所选来源及必要依赖的定向检查，不附加无关整场 |
| 提交边界、状态生命周期、RNG、事件顺序 | 检查本次改变的行为；只有实际可能破坏原子性/顺序时补对应失败或顺序检查 |
| 组件检查不能覆盖的跨层接线或可用功能交付 | 一条实际使用该改动的整场路线；多个相关修改合并后运行一次 |
| 归档、恢复、序列化、指纹或确定性重放路径 | 必要时独立文件回放一次，可复用本批已有归档；普通公式/内容调整不自动触发 |
| 执行热点、状态结构、缓存或序列化 | 固定性能基准场景的启动与单条命令耗时，与交接中的基线比较 |
| UI 表单与展示 | 对应请求或交互检查，不因调用内核就自动加跑整场 |

数值对照是内容正确与否的判据：对照值取自游戏实测或成熟计算器，只用于检验，不写成规则。
取不到对照值的条目标为“未对照”，不计入完成。来源审计不属于上表任何一行的必要证据；
追查具体问题时可以开启，不为新内容补审计生产者、防伪检查或反例矩阵。

测试模块分普通回归与 `integration`；真实完整编译/场景按需显式运行。
历史 tools 只有仍被当前测试、生产检查或明确任务引用时才承担现行职责；不默认运行阶段套餐，
不新增阶段验证器，也不随新内容维护旧验证器。
删除或移动工具前检查所有调用者；测试仍引用的辅助函数不能连同历史脚本直接删除。

非必要不跑整场或独立 replay，两者不是绑定套餐。已有归档满足回放验证时不重新生成战斗；
定向检查已回答改动风险且通过即结束，不再叠加同一路线、同义负例或全部历史回归。
只有新改动影响已验结果、实际失败或具体未解疑点才重跑相关检查；追加检查前用一句话说清
要发现什么尚未覆盖的错误，不能只用“保险起见”或“动了共享文件”作为理由。
全量回归仅用于影响广泛且定向检查不足的改动或版本验收；全目录编译仅用于声明目录完整性
或来源升级。不得把每个小修复称为里程碑来触发全套验证。

2026-10-10 资源约定：来源编译日常使用动作切片或已有场景范围，不按每个修复点重建默认
全目录。全目录失败先用其真实输入补定向检查、集中修复，再验收；已经通过且未受后续改动
影响的证据继续复用。全目录编译、完整回归和整场生成/回放串行运行，并记录峰值内存。

## 成本与交付

- 编译、整场、全量回归等重任务及性能调查记录可取得的实际耗时/峰值；轻量检查不另做
  成本报告，不能测得的项不编造。
- 性能按 [PROJECT_GOALS.md](../PROJECT_GOALS.md#性能预算) 的预算验收，基准场景和当前基线在交接维护。
- 优先定位重复工作。性能改动使用同一来源、场景、命令与验收边界比较；内部微测不能冒充整场加速。
  不通过放宽原子提交或确定性提速；为审计服务的证据构造是瓶颈时可以改为按需生成。
- 大归档先分析已有产物，再定位证据生产者，避免用重复完整战斗定位体积。
- 交付写清完成的名单条目、数值对照结果、性能基准、修改原因和保留限制。同线程复查不称为独立审计。
- 执行说明写清目标、输入、步骤、完成条件和必要检查，省略具体执行者、模型分工和对话背景。
- 当前事实放交接，操作放 CLI/测试入口，永久约束放架构文档；不复制多份进度。
