# 本地执行与验证约定

## 0. 当前本地工作方式

目标是尽量还原实际战斗行为。保留 L0 来源编译、L1 通用执行、L2 内容装配、L3 外部操作，
以及来源可追查、原子提交、确定性 RNG、settlement 和 replay；不完整复刻原生引擎的内部组织。
当前任务与支持边界只在 [CODEX_HANDOFF.md](../../CODEX_HANDOFF.md) 维护。

2026-10-10 用户明确：成本应带来实际推进，不限制单次运行成本；按里程碑评估总收益。
工作按可用成果或可证明的维护收益组织，同根问题集中修复，不以单个 blocker、
文件拆分数量或测试数量作为交付。

## 事实、实现与范围

- 先定位正式调用链与生产权威，优先复用现有机制、参数和装配入口；只补真实缺口。
- 普通接线与修复在已授权范围持续完成；不自动触发 MCP、固定执行角色、审批卡或逐卡 PR。
- 特殊机制由具体内容推动；旧阶段未勾选不等于没有实现，也不扩大当前任务范围。
- 未知规则、来源缺口、实现缺口、接线问题和未验证分别记录；未知只阻断实际依赖。
- PR #8 用户已确认结论可经编译/注册进入类型化规则，注明研究来源，不伪称 TBGD 来源。
  涉及规则变动时只读核对相关研究增量与不可变版本；争议/暂停结论不升级为正式规则。
- 游戏观察记录版本、构筑、目标、操作、时间戳与可见值，区分观察和解释；
  跳字数量不代表内部请求数，未知构筑的数值不能补公式。
- 新依赖、下载、扩大权限、创建或覆盖 uv 环境先询问；复用工作区已有环境。
- 公共接口或归档不兼容时先明确兼容要求。用户已在本轮明确不兼容旧规则指纹归档。
- 没有另行授权不提交、不推送、不创建 PR，不更新 TBGD submodule 指针。
- 手工编辑使用 apply_patch；临时数据写 /tmp，保留用户无关改动。

## 实施闭环

1. 明确本批可观察成果、受影响权威、调用者和必要检查。
2. 形成最小完整改动；结构整理与规则变化分别实施，便于定位回归。
3. 运行受影响检查，集中修复同一根因。
4. 批末验收实际成果，更新短交接与剩余限制。

如果两轮修复同一根因仍无新进展，重新定位或拆分任务；不通过增加验证器、扩大扫描
或反复加载历史文档代替决策。复杂跨领域修改才补窄执行说明，普通任务不强制新卡或报告。

## 验证选择

现行命令见 [tests/README.md](../tests/README.md)，本节只定义何时使用。

| 改动 | 必要证据 |
| --- | --- |
| 文档、导航 | 链接、事实一致性、diff |
| 单一规则或来源形状 | 受影响测试及一个能捕获该错误的行为检查 |
| 来源范围、引用关系 | 所选来源与必要依赖闭合；只对声明完整的目录核对分母 |
| 执行、状态、RNG、事件 | 正常行为、相关失败零提交、顺序与来源保持 |
| 场景或公共执行链 | 受影响定向检查，加现有或新增路线的独立文件回放 |

测试模块分普通回归与 `integration`；真实完整编译/场景按需显式运行。
历史 tools 只有仍被当前测试、生产检查或明确任务引用时才承担现行职责；不默认运行阶段套餐。
删除或移动工具前检查所有调用者；测试仍引用的辅助函数不能连同历史脚本直接删除。

同一路线批末生成一次归档、独立文件 replay 一次，复用其验证结果，不额外叠加同场内存回放。
新改动、实际失败或未解决疑点才重跑相关检查。全量目录检查仅用于目录完整性声明，
全量回归用于重大共享改动或里程碑，不能代替直接行为证据。

## 成本与交付

- 记录实际墙钟、峰值内存、产物大小和可获得的 token 用量；不能测得的项不编造。
- 优先定位重复工作。性能改动使用同一来源、场景、命令与验收边界比较；
  内部微测不能冒充整场加速，也不通过删审计事实或放宽提交检查提速。
- 大归档先分析已有产物，再定位证据生产者，避免用重复完整战斗定位体积。
- 交付写清成果、修改原因、实际验证、保留限制。同线程复查不称为独立审计。
- 当前事实放交接，操作放 CLI/测试入口，永久约束放架构文档；不复制多份进度。
