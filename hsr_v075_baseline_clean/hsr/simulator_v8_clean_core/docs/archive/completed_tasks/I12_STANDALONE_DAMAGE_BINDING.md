# I12 独立伤害逐任务绑定修复契约

> 历史归档（2026-10-21 整理）：下文状态、任务顺序和验收要求仅反映记录当时。
> 当前工作以[交接](../../../../CODEX_HANDOFF.md)和[执行约定](../../AGENT_WORKFLOW_AND_VALIDATION.md)为准；归档不代表本轮重新验收。

当前进度与验收结论只在[当前交接](../../../../CODEX_HANDOFF.md)维护；本文固定本批实现边界与验收要求。

## 目标与调用链

接通同一独立能力中不同伤害任务各自的倍率、属性基准、技能等级、目标及削韧来源。
参数沿正式 TriggerAbility 引用传播，最终只为实际消费参数的具体子伤害任务生成绑定。

涉及 `tbgd/lowering.py` 中的 `_bind_character_queue_damage`、
`_project_standalone_skill_formula_bindings`、`_lower_standalone_hit_profiles`、
`_direct_damage_binding_lookup` / `_direct_basis_binding`，以及正式伤害/削韧发射、执行与审计。

## 设计约束

1. **传播与物化分开**：编译内部沿正式 TriggerAbility 引用传播参数可用上下文。中间能力
   不造成伤害、或不消费该参数，都不能截断后续传播；只有实际消费参数的具体伤害任务才
   物化 SkillFormulaBindingIR，中间节点不输出悬挂绑定。
2. **消费始终逐任务**：最终绑定身份包含子伤害任务，倍率、属性基准、技能等级及来源不能
   跨任务借用。相同 param_index 不代表同一参数，相同 hash 也不能代替任务身份。
3. **唯一性按完整表达式确认**：本批继承仅支持单参数命中；无自有绑定的复合继承程序、
   缺失参数和无法消解的多候选保持拒绝。可证明为同一正式参数的重复声明可去重；不同
   基准或来源不能因数值相等而合并，也不能以排序、setdefault 或首个候选消歧。
4. **自有绑定与边界保持**：具体任务已有正式自有绑定时复用它，不覆盖、不连带阻断其它
   任务继承。已有 Topaz 自有复合公式继续可用；本批不放宽 AttackType、目标或削韧准入。
   普通技能和最终任务绑定保留常数时间查找，不恢复能力级消费者兜底。
5. **结果与来源一致**：剖面选中的 binding_id、伤害发射的基准绑定和实际执行审计须一致。
   调整任务、绑定和来源输入的枚举顺序不得改变语义；引用循环或超出现有传播深度上限时
   必须有限结束，不误放行。

## 固定验收清单

以下是同一批必须核对的独立行为，复用现有检查，缺失处在既有测试模块补最小用例，不做
组合穷举，不默认全目录编译或全回归：

| 验收场景 | 必须满足的结果 |
| --- | --- |
| 直接单参数继承 | 只生成实际子伤害任务绑定，父任务及无关任务不能借用 |
| 经无伤害或未消费该参数的中间能力继续触发 | 最终子任务可继承，中间节点没有悬挂绑定 |
| 多子任务共用 hash；同槽位使用不同 hash | 每个任务均有自己的绑定，基准与来源不串用 |
| 子任务已有自有绑定 | 自有绑定不变，其它任务按自身条件独立处理 |
| 缺失、多主基准或不同来源候选冲突 | 明确拒绝，不能借继承兜底；输入顺序不影响结果 |
| 循环及现有深度上限 | 有限结束，不产生越界准入或无消费者绑定 |
| 正式消费者的成功与失败路径 | 实际执行并审计成功；失败状态、mutation、RNG 均不泄漏 |

测试须调用实际投影生产者和消费者；仅手工拼好最终绑定不能证明投影正确。组件输入须
明确标注，不能冒充真实来源整图。每轮改动后复跑这组受影响检查，通过后一次性交回验收。
