# 非记忆、非欢愉角色共享机制缺口归并

状态：现行规划基线，不是实现完成证明，也不是阶段 checklist

代码基线：`8d8f746` 及本次只读工作区

来源范围：79 条已发布角色记录、79 份角色主能力文件、1 份共享角色运行时文件

范围依赖：`CHARACTER_ABILITY_SCOPE_CLASSIFICATION.md`

## 1. 目的与结论

本文把已经发现但尚未完整执行的角色内容按根因归并，回答三件事：

1. 哪些缺口其实属于同一个共享机制。
2. 哪些能力已经存在，只是来源接线、lowering 或准入口径过窄。
3. 后续应该以什么顺序补通内核，避免按角色复制规则和验证器。

本轮按用户裁决暂不处理记忆和欢愉两条新命途。剩余 79 条角色记录都能生成正式基础
战斗单位，但没有任何一条可以因此被视为“全技能、全行迹、全星魂已完成”。

核心结论是：当前角色工程应按 19 个共享机制包推进，其中 17 个负责来源接线或通用战斗
语义，1 个负责混淆/缺失来源，1 个负责最终目录审计。不得再建立“每个角色一套实现”或
“每个阻断字符串一张执行卡”。

## 3. “尚未实现”必须先分性质

后续审计遇到 blocked 时，必须先归入以下一种性质，再决定是否写代码：

| 缺口性质 | 含义 | 正确处理 |
|---|---|---|
| 范围退役 | 动画、镜头、音效、HUD、客户端控制、AI 或统计被旧 lowering 当成待执行效果 | 从战斗来源链退役，保证零 mutation、零事件、零 gameplay RNG |
| 数据投影 | 原始操作本身属于 UI/客户端，但携带特殊资源、目标持续性或单位拓扑等战斗事实 | 只 lower 所需事实为类型化契约，不执行原始操作 |
| 来源接线 | 真实能力、动作阶段、共享来源或内容节点存在，但没有唯一接到角色卡和能力图 | 修复来源关联；没有可靠唯一关系时保持 blocked |
| 准入缺口 | 通用执行器已经存在，但 lowering、事件 payload、目标或回调白名单拒绝了真实来源形状 | 扩展通用类型契约和准入，不复制第二套执行器 |
| 语义缺口 | 当前内核确实没有该类战斗规则，或已有模型不能表达真实规则 | 设计并实现通用机制，再由内容卡引用 |
| 来源语义缺口 | 名称混淆、字段语义不明、真实 ability 缺失或候选冲突 | 保留来源并 fail-closed；先解码或等待可靠来源，禁止猜测 |
| 目录闭合缺口 | 单项机制已经可执行，但尚未证明所有技能、行迹和星魂都已正确接入 | 做目录审计和少量真实纵切，不再创建新 runtime 规则 |

同一个节点可能有“主要根因 + 下游依赖”。例如状态回调里的 `AddModifier` 因事件未准入而
blocked，主要根因属于事件包；事件打通后若状态 payload 仍不完整，才继续归状态包。不能把
两个阶段都提前统计成两套独立实现。

## 4. 共享机制包总览

### 4.1 来源、构筑和执行骨架

| 包 | 统一负责 | 当前事实 | 完成边界 |
|---|---|---|---|
| `M00` 范围退役与战斗数据投影 | 特殊资源、目标持续性、队形/拓扑和环境输入；表现、客户端、AI、统计退役 | 445 个投影/环境节点，涉及 73 条角色记录 | 每个投影都有等价类型化契约；退役分支不能产生战斗结果 |
| `M01` 来源图、动作阶段与能力绑定 | 共享角色能力、技能入口、强化阶段、被动入口和 standalone ability 的唯一关联 | 17 条记录有 19 个动作绑定缺口；共享角色能力尚未正式接线 | 每个动作阶段唯一关联真实来源，无法唯一关联的记录为明确 source gap |
| `M02` 最终构筑激活与内容绑定 | 最终技能等级、行迹、星魂、静态贡献和动态机制引用 | 901 个构筑选择节点；79 条角色均受影响 | 构筑阶段消费所有最终选择，runtime 不再判断养成/解锁过程；同一效果不重复绑定 |
| `M03` 类型化数值表达式与动态值 | 动态值定义、读取、变换、复制，以及从属性、状态、伤害、治疗、护盾和资源取值 | 24 个来源族、2,371 次出现，覆盖 79 条角色；现有 evaluator 和动态值通道可复用 | 所有变体归入统一的“读取-计算-写入”模型，缺绑定或非法公式原子 blocked |
| `M04` 目标表达式与实体关系 | 目标别名、查询、过滤、合并、排序、截取、重定向及 owner/队伍/战斗事件关系 | 23 个来源族、12,732 次出现，覆盖 79 条角色；现有 `TargetSystem` 可扩展 | 目标从 action definition 和类型化上下文求得，不按角色名或固定 ID 分支 |
| `M05` 通用条件求值 | 数值比较、身份关系、集合量词、动作窗口、伤害/状态/资源上下文判断 | 86 个来源条件族；45 个尚未被 evaluator 接纳，其中 43 个出现在角色主文件、2 个只在共享文件 | 每个条件只读取类型化上下文并返回真/假/blocked；构筑选择条件不留在 runtime |
| `M06` 能力图控制流与模拟时序 | 模板引用、条件分支、循环、触发、并行、命中序列和真正影响结算顺序的等待 | 31 个来源族、8,651 次出现，覆盖 79 条角色；`AbilityTaskSystem` 已有部分骨架 | 顺序、原子性和失败传播可重放；动画时间线和物理弹道不进入模拟 |
| `M07` 事件窗口与状态回调派发 | 动作、伤害、治疗、状态、资源、单位和波次生命周期事件及其 typed payload | 125 个战斗事件族、2,405 次事件出现，另有 11 次自定义事件任务；覆盖 79 条角色 | 生产者、事件身份、payload、派发和 callback 在同一提交链闭合，不按事件名复制 handler |

`M03` 至 `M07` 是后续角色机制的公共执行语言。它们不应只为某一名角色补一个 case；每次
扩展都必须从真实来源形状形成可复用的类型化能力。

### 4.3 来源解码与最终闭合

| 包 | 统一负责 | 当前事实 | 完成边界 |
|---|---|---|---|
| `M17` 混淆或缺失来源解码 | 混淆节点、缺失 ability、候选冲突和无法证明的字段语义 | 当前范围剩 6 个混淆战斗族、110 次出现、影响 16 条角色；另有大黑塔真实 ability 缺失 | 只有来源、字段形状和上下游共同证明语义后才能转交其他机制包；否则保持 blocked |
| `M18` 目录闭合与完成审计 | 79 条角色的技能、行迹、星魂、动作阶段和来源追溯总账 | 当前所有角色都有基础构筑，但 0 条已证明全机制闭合 | 每个纳入来源都为 executable、明确 source gap 或用户接受的 deferred；代表纵切不能替代全目录覆盖 |

`M18` 不是新的 runtime 子系统，也不允许产生第二套规则。它只消费前面机制包的真实结果，
告诉我们哪些角色还缺什么。

## 5. 已知接线缺口如何归并

### 5.1 动作和能力来源

17 条角色记录共有 19 个动作绑定缺口，全部先归 `M01`，不应分别变成 19 个机制：

- 16 条记录缺少可唯一关联的 ability phase。
- 飞霄和男女毁灭开拓者存在 entry ability / skill ability list 缺口。
- 男女毁灭开拓者各同时有两种缺口。

这里要先区分可提交动作、强化阶段、被动入口和演出 ability。不能把“名字相似”或“同技能
的另一个阶段”当作来源关联证据。

### 5.2 行迹和星魂

79 条角色的现有构筑诊断归并到 `M02`：

| 现有诊断 | 受影响角色数 | 共享根因 |
|---|---:|---|
| 星魂槽没有运行时效果来源 | 76 | 星魂定义到静态贡献/能力图的统一绑定 |
| 行迹节点没有结构化效果来源 | 61 | 行迹节点到静态贡献/能力图的统一绑定 |
| 星魂额外效果尚未准入 | 57 | 额外效果身份和真实来源关联 |
| 行迹额外效果尚未准入 | 52 | 静态与动态分流及能力引用 |
| 行迹 ability 尚未正式消费 | 39 | 构筑装配结果到 runtime 机制引用接线 |
| 星魂能力图缺失或歧义 | 28 | 来源唯一性或真实 source gap |

这些数字可以在同一角色上重叠，不能相加成任务量。实现目标是建立一次通用内容绑定链，
然后由目录审计批量重新计算。

### 5.3 条件族

`M05` 当前有 45 个来源条件族尚未进入 evaluator。高复用项如下：

| 条件语义 | 涉及角色数 | 出现次数 | 应复用的上下文 |
|---|---:|---:|---|
| 当前生命值比较 | 17 | 48 | 单位属性/生命状态 |
| 是否为当前行动实体 | 13 | 18 | 行动窗口和队列 |
| 目标集合中任一满足 | 11 | 36 | 目标表达式和子谓词 |
| 是否为战斗事件实体 | 10 | 20 | 实体关系 |
| 目标是否不可选中 | 8 | 18 | 单位生命周期 |
| 角色命途判断 | 6 | 36 | 数据卡身份 |
| 字符串参数比较 | 5 | 10 | 类型化事件/动作参数 |
| 怪物阶级比较 | 5 | 6 | 怪物卡身份 |
| 战技点比较 | 3 | 8 | 资源上下文 |
| 未使用终结技次数比较 | 3 | 3 | 行动/技能队列 |
| 是否为分摊伤害 | 3 | 3 | 伤害窗口 |

其余 32 个角色文件条件族和 2 个共享文件条件族大多只出现于 1 至 2 条角色，但仍应按
“比较器 + 类型化取值器 + 实体/事件上下文”组合实现，不能为低频来源写角色专属 if。
`ByRankActivated` 和 `BySkillPointActivated` 属于最终构筑解析，应由 `M02` 消费，不应为了
清理旧 blocked 把它们扩进 runtime evaluator。

## 6. 旧 blocked 记录的根因折叠规则

当前生产盘点仍混有旧 lowering 的窄准入和表现分支。后续不得按报错数量排优先级：

| 旧阻断形状 | 主要归属 | 后续可能依赖 | 禁止的处理 |
|---|---|---|---|
| 状态回调事件未准入 | `M07` | 对应任务再归 `M03`/`M08`/`M09` 等 | 为每个事件复制 callback executor |
| 回调中的状态、动态值或资源指令未准入 | 先 `M07`，再归指令所属领域包 | typed payload 和来源绑定 | 在 callback 内另写一套效果 handler |
| 构筑等级/行迹/星魂条件不可执行 | `M02` | `M01` 来源关联 | 把最终构筑选择留到战斗中反复判断 |
| 目标别名、重定向或集合条件未准入 | `M04`/`M05` | `M07` 事件上下文 | 按角色或技能名返回固定目标 |
| 资源公式不支持某种数值表达式 | `M03`，结果由 `M10` 消费 | 类型化来源绑定 | 在资源 handler 里手算一套公式 |
| 模板、循环、触发或命中序列未准入 | `M06` | `M03` 至 `M05` | 在验证器里手工展开任务顺序 |
| 动画、特效、HUD、客户端 `_CL` 事件被报 unsupported | `X00` 或 `M00` | 仅在携带战斗事实时投影 | 为清零 unsupported 实现客户端行为 |
| 缺失 ability phase、entry ability 或共享来源 | `M01` | 可能转为 `M17` source gap | 用相似名称、固定 ID 或文本补绑定 |

例如旧盘点中 `AddModifier`、`StackProperty`、`SetDynamicValue` 在普通动作里已有执行路径，
但在大量状态回调中因事件或 callback task admission 被拦截。这里首先是一个 `M07` 接线问题，
不是三个新效果系统，更不是按每名角色分别实现。

## 7. 六个混淆战斗族

当前 79 条角色范围内只剩以下 6 个混淆族。它们统一归 `M17`，但记录可能的下游机制，
便于解码后直接复用而不是新建 handler：

| 来源族 | 次数 / 角色数 | 已确认字段形状 | 候选下游 |
|---|---:|---|---|
| `LAJIKDENEOO` | 88 / 12 | 目标、命名动态值、数值表达式，部分带 `Set` 操作 | 高概率转 `M03`，未解码前不得执行 |
| `NKLOMENKLHK` | 13 / 12 | 与上一族使用相同目标和动态值名称 | 高概率是 `M03` 的配套定义/初始化 |
| `IKDAKCBKFAB` | 3 / 2 | 位于 `PreCheck`，比较未使用的同标签插入次数 | `M05` + `M11` |
| `FFMONJGCKDI` | 3 / 1 | 位于海瑟音回调任务，只携带一个数值表达式 | 暂不能可靠归入动态值或状态语义 |
| `LAPKGFCDPCD` | 1 / 1 | Archer ability 启动时的两个布尔字段 | 语义不足，保持 blocked |
| `LPMGDCDFOOE` | 2 / 1 | 不死途 ability 启动时的目标和布尔字段 | 语义不足，保持 blocked |

大黑塔追加攻击分支引用的 ability 在当前来源中没有定义，不属于这 6 个混淆族。它是独立的
真实 source gap；除非数据源补齐或发现可靠的现有定义，否则 `M18` 必须持续记录 blocked。

## 8. 依赖顺序

机制包按以下依赖推进，不按角色复杂度表顺序推进：

1. `M00` 清除假缺口，同时固定投影边界。
2. `M01` 和 `M02` 建立角色来源与最终构筑接线；`M17` 可并行做只读解码。
3. `M03` 和 `M04` 补齐统一数值、目标和实体上下文。
4. `M05` 和 `M06` 在前两者上完成条件和能力图控制流。
5. `M07` 统一事件生产、payload、派发和状态回调。
6. `M08` 至 `M16` 按真实缺口补领域语义；已有系统只做差量扩展，不整体重写。
7. `M18` 重算全目录，剩余 gap 再回到对应机制包，不直接落到角色专属修复。

`M12` 至 `M16` 虽然来源角色较少，仍依赖前面的通用上下文和事件链。为赶进度提前写角色
专属纵切，只会在后续角色中重复返工。

## 9. 角色覆盖与代表纵切

代表角色只用于证明共享机制从真实数据到正式战斗的完整链，不能代替 79 条角色目录审计。
代表数量不得预先写成 8 名或任何固定数字，选择过程必须是：

1. 先由 `M18` 生成“角色 -> 尚未闭合机制包 -> 具体来源形状”矩阵。
2. 每次选择能覆盖最多未证明来源形状、同时不引入未完成上游依赖的真实角色。
3. 一个机制包可能只需 1 条纵切，也可能因存在多种 payload/生命周期形状需要多条。
4. 纵切全部通过后仍要运行轻量目录审计，确认其他角色只是在复用已证明形状。

按来源覆盖看，`M03` 至 `M09` 涉及全部 79 条角色；`M10` 涉及 72 条，`M11` 涉及 62 条，
`M12` 涉及 15 条，`M13` 涉及 22 条，`M14` 涉及 8 条，`M15` 涉及 9 条。这个分布说明
前半段必须做通用基础设施，但不能据出现次数线性估算开发量。

## 10. 每个机制包的完成标准

任何机制包只有同时满足以下条件，才能交给 `M18` 视为已闭合：

- 该包纳入的所有真实来源形状都有确定的 typed lowering；未知形状保持明确 blocked。
- runtime 只消费 Canonical IR、数据卡和装配结果，不读取 raw 或 source trace 决定行为。
- 没有角色名、技能名、固定 ID、固定文件名或文本推断分支。
- 同一通用语义只有一个生产实现；普通动作、状态回调和战斗事件复用同一 effect contract。
- 失败在提交前 fail-closed，state、mutation、event 和 RNG 保持一致。
- 可执行结果原生生成 settlement、来源审计和 replay 证据。
- 聚焦验证只覆盖本包新增契约和必要 direct；目录层只重算覆盖矩阵，不重复完整战斗验证。
- 完成报告明确区分 executable、source gap、外部内容依赖、用户接受的 deferred 和排除项。
