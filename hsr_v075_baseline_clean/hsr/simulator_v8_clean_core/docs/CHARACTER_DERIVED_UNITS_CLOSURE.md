正确处理属性、资源、归属变化、退出和再次创建，并能继续公开操作。

## 实现原则与约束

实现路径、修改范围和顺序由实际依赖决定。先结合来源、现有规则与完整相关调用链，
识别本包可见缺口并归并共同根因，再集中完成相关修改。分析服务于实现，
不另设分析报告、逐项审批或固定的角色推进顺序。

已知玩法优先通过现有 IR、规则注册和执行系统表达；TBGD 与可靠机制资料均可作为正式依据。
不要求逐项复刻原生任务、混淆协议或客户端内部组织。
已确认无战斗影响的表现内容按现有边界处理；影响战斗的选择、资源、目标和时序必须保留。

- runtime 消费正式规则和已装配输入；来源链接、审计路径和普通事件 payload 不授予行为许可。
  瞬时事实由对应领域的类型化生产者提供。
- 创建者、当前持有者、属性来源和行动者按正式规则区分；属性与参数取实际构筑和有效等级。
  出生快照、后续同步及继承例外保留各自语义，不统一猜测为实时跟随。
- 生命周期正确处理退出、主人变化、替换与重召唤，清理失效关系、状态、动态值和队列，
  保留无关单位与兄弟实例；新实例不继承旧实例的残留状态。
- 状态变化通过正式 mutation 原子提交，保留原生事件、settlement 和来源；
  实现阻断不改变状态或 RNG，已验收角色、装备和怪物行为不得回归。

其它项目约束和验证口径沿用 [本地执行与验证约定](AGENT_WORKFLOW_AND_VALIDATION.md)。

## 验收标准

1. 表中内容从正式构筑与公开操作实际可用，各自独有机制已经消费。
   创建成功、主人造成伤害或整场胜利，都不能代替派生单位自身行为的证据。
   相关事件和结算应能区分实际行动者、目标、资源与效果。
2. 属性、目标、资源、行动时机和生命周期符合正式规则；连续使用、退出与再次创建后仍能
   继续合法操作。新改动涉及的原子失败边界有对应检查，既有覆盖足够时直接复用。
3. 先审查完整差异、正式调用者和共同不变量，再集中运行必要检查。
   源码可确定的缺口通过分析集中解决；运行用于回答具体动态疑问和验证跨层接线，
   避免以反复从入场试跑作为主要需求发现方式。
4. 复用或补齐 [派生单位路线检查](../tests/test_r07_derived_unit_routes.py)、
   [共享机制检查](../tests/test_r07_shared_mechanism_contract.py) 及已有相关检查。
   测试组织和场景组合按覆盖需要决定，不固定路线数量、队伍、执行顺序或测试套餐。
   正式路线经公开操作形成所需战况；组件构造的局部状态只承担组件证据。
5. 至少保留一条正式胜败路线；其它路线达到目标行为且可继续提交即可结束。
   未受后续改动影响的证据复用；只有归档、身份或确定性路径受影响时才补必要的独立 replay。
   编译、整场与完整回归继续串行持有 `/tmp/hsr-v8-validation.lock`，验证期间固定源码。

最终交付包括可用行为、共享修改及原因、实际验证结果和准确剩余依赖。
编译可用、运行通过、审计通过与尚未验证分别记录。
