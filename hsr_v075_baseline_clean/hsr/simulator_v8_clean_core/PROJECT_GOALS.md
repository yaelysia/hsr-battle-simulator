# 项目目标与完成定义

## 最终目标

本项目要建立一个可供人工操作、UI 和外部推演器使用的《崩坏：星穹铁道》战斗模拟器。
给定合法战斗配置和一串外部选择，内核应产生规则一致、确定可重放、来源可追查的战斗结果。

外部推演器负责像玩家一样控制敌我双方：查询合法动作和目标、选择分支、提交命令并读取结果。
内核负责规则，不实现敌方 AI、自动战斗策略或通关搜索算法。

## 功能范围

最终模拟范围包括：

- 角色、怪物、召唤物、光锥、遗器和关卡环境的合法战斗构筑；
- 等级、晋阶、行迹、星魂、技能等级和最终装备词条形成的入场状态；
- 双方合法动作、目标、行动窗口和资源约束；
- 伤害、治疗、护盾、韧性、击破、状态、队列、波次、死亡、复活和召唤生命周期；
- 随机选择与可重放 RNG 账本；
- 每次状态变化的 mutation、settlement、snapshot、source audit 和 replay；
- 面向 UI 与推演器的只读查询和命令提交契约。

不属于战斗模拟的内容默认排除：

- 抽取、掉落、商店、背包和服务端资产管理；
- 角色或装备的材料消耗、强化历史、合成和定向生成；
- 动画、镜头、音效和纯展示逻辑；
- 游戏客户端敌方决策策略、自动配队和自动战斗。

若排除项的最终结果会进入战斗，只接收规范化成品，例如最终遗器等级与词条，不复刻其养成过程。

## 架构目标

正式规则只能沿以下方向流动：

```text
TBGD raw -> compiler/lowering -> Canonical IR / 数据卡 IR
         -> RuleBook -> 构筑与场景准入 -> 通用战斗内核
         -> 查询 / settlement / snapshot / replay
```

完成后的系统必须满足：

- 来源层解释 raw 数据，runtime 不读取 raw、TextMap 或 source trace 决定行为；
- 角色、怪物和装备数据卡组合通用机制，不复制第二套执行器；
- 构筑装配负责把内容定义和玩家输入变成正式入场结果；
- 战斗内核只处理类型化规则和已准入输入，不按名称、固定 ID 或文件名特判；
- UI 与推演器不自行推算伤害、目标、资源、状态或动作合法性；
- 未知或矛盾状态在构造、准入或原子提交边界 fail-closed。

## 正确性目标

同一初始状态、命令序列和 RNG 输入必须得到同一：

- 合法性判定与目标集合；
- mutation、event 和 RNG 消费顺序；
- 最终状态与胜负；
- settlement、snapshot 和 replay 结果。

每个正式 mutation 必须能反查到 Canonical IR 节点和真实 TBGD 来源。失败请求不得留下部分状态、
队列、事件或 RNG 消耗。验证工具只证明这些生产不变量，不能成为规则权威。

## 完成层级

项目中的“完成”必须说明层级，禁止把底座完成等同于内容全量完成：

1. **机制底座完成**：通用领域规则可正确执行，但不代表所有内容已接入。
2. **内容定义完成**：来源已投影为数据卡或 IR，但不代表可以正式战斗。
3. **构筑可准入**：指定内容可生成合法入场单位，但不代表全部动作机制闭合。
4. **战斗可执行**：动作、目标、结算、事件和状态链可正式运行。
5. **内容目录完成**：声明范围内每个 gameplay 来源都已执行、明确排除或有真实 source gap。
6. **模拟器可用**：配置、战斗、结算回溯和外部操作接口形成完整用户流程。

任何阶段都必须区分 `executable`、`blocked`、`deferred` 和 `not_proven`。当前进度只在
[`../CODEX_HANDOFF.md`](../CODEX_HANDOFF.md) 维护，不写入本稳定目标文档。

## 质量优先级

```text
最终成品完整性 > 内核干净程度 > 来源可追查 > 验证可重复 > 旧版兼容
```

旧 v7 和旧 model pack 只可帮助定位历史意图，不能补规则或约束 v8 架构。详细永久红线见
[`ARCHITECTURE_BOUNDARY_CONTRACT.md`](ARCHITECTURE_BOUNDARY_CONTRACT.md) 和
[`FORBIDDEN.md`](FORBIDDEN.md)。
