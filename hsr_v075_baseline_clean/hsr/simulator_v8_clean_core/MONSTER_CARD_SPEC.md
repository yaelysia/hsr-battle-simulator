# v8 怪物卡规范

怪物卡位于来源编译层和内容装配层之间。它把怪物身份、面板、动作、能力、目标和召唤关系投影为
类型化内容，但不实现第二套战斗规则，也不实现敌方 AI。

## 职责边界

- 怪物卡构建可以读取 TBGD 怪物表、怪物能力、状态定义和 AI 配置来源。
- TextMap 只提供展示名称和说明，不能决定动作、目标、倍率或状态效果。
- runtime 只读取 Canonical IR、怪物数据卡、RuleBook 和已准入战斗输入。
- 怪物专属差异进入动作定义、能力图、状态或召唤关系，不进入核心名称和固定 ID 特判。
- 缺动作、目标、能力、公式或必要战斗上下文时，受影响内容结构化 blocked 且状态不变。

## 主要来源

- `MonsterConfig.json`：怪物实例、技能列表、弱点、抗性、召唤关系、覆盖参数和能力入口。
- `MonsterTemplateConfig.json`、`MonsterTemplateUniqueConfig.json`：模板、档位、基础面板和配置引用。
- `MonsterSkillConfig.json`、`MonsterSkillUniqueConfig.json`：怪物技能定义、参数和阶段信息。
- `Config/ConfigCharacter/Monster/`：动作触发、目标信息、主动与被动能力入口。
- `Config/ConfigAbility/Monster/`：能力任务、效果、动态值、状态与事件来源。
- 状态和 modifier 定义：状态生命周期、回调和监听来源。
- `Config/ConfigAI/` 及 AI 序列字段：仅用于区分决策策略、展示信息和真正的战斗约束。

`MonsterSkill.ModifierList` 只能按其实际技能语义投影，不能自动当作怪物常驻被动。
`MonsterConfig.AbilityNameList` 只是机制入口之一，不能代表完整被动集合。

## 数据卡内容

怪物卡应以类型化结构保存：

- 怪物、模板、档位和战斗实体身份；
- 基础面板、弱点、抗性和必要资源；
- 原始技能顺序及对应动作定义引用；
- 主动能力、被动能力、状态回调和召唤关系入口；
- 每个动作的目标契约、参数绑定和可用性约束；
- 与阶段、形态、波次或召唤生命周期有关的战斗规则；
- 关键记录的来源路径、记录身份和字段位置；
- display-only 名称和说明。

来源中的任意字典不能直接成为 runtime payload。混淆字段在语义未证明前保留来源并阻断，不得改名为
自造规则。

## 动作与能力

普通怪物技能和特殊玩法技能必须使用不同命名空间，不能因数值 ID 相同互相借用定义。

一条正式怪物动作至少闭合：

```text
怪物卡 -> 动作定义 -> 目标契约 -> 能力图/领域效果 -> 原子提交
       -> mutation/event/RNG -> settlement/source audit/replay
```

外部调用者只能提交内核查询结果中公布的 actor、action、level 和 target choice。动作执行失败不得
回退默认目标、旧解释器或直接伤害路径。

状态、伤害、治疗、护盾、资源、队列和召唤效果必须复用角色侧相同的通用领域系统。怪物 ability
不能复制一套专用执行器。

## 目标契约

动作的可选目标和实际效果范围属于动作或效果的类型化目标表达式。runtime 不读取 raw 字段临时解释。

- 查询阶段返回合法目标选择，不产生 mutation。
- 提交阶段校验选择身份、actor、动作所有权和当前窗口。
- 执行阶段只消费已接受的不可变目标上下文。
- 任一目标表达式、实体关系或筛选条件 blocked 时，相关效果原子失败。
- 随机目标必须进入统一 RNG 计划和 replay 账本，不能使用本地随机或列表首项替代。

具体已支持 family 和剩余 gap 属于当前阶段计划或来源账本，不写死在本稳定规范中。

## 敌方决策边界

本项目不执行游戏客户端的敌方 AI。轮到敌方单位行动时，内核应像处理玩家单位一样：

1. 根据怪物卡和当前战斗状态给出合法动作；
2. 给出每个动作的合法目标与必要参数；
3. 由用户、UI 或外部推演器选择；
4. 通过标准命令和同一 Combat Core 执行。

`AIPath`、`AISkillSequence`、目标偏好、随机策略和评分逻辑默认属于决策策略，不能成为 runtime 的
动作选择权威，也不能因“复杂 AI 未实现”阻断一个本来规则完整的怪物动作。

若 AI 配置中的某个字段实际表达强制行动、阶段锁定或其他会改变合法动作集合的战斗规则，必须先以
独立来源证明其不是选择策略，再投影为通用的可用性、阶段或事件约束。未完成该证明时只能保留来源
并标记 `not_proven`，不能执行整个 AI 文件。

现有历史固定序列候选可作为来源审计或迁移参考，但不是最终动作查询契约，也不能代替外部选择。

## 召唤、状态与生命周期

- 怪物召唤出的普通怪物优先复用已有怪物卡，并记录 owner、summoner、team 和生命周期。
- 后台、场外或不可选单位必须通过类型化存在状态和关系表达，不能只靠是否位于行动队列判断。
- 技能挂载状态时，modifier、目标、概率、叠层、持续时间和监听入口必须完整准入。
- callback/listener 只有在事件 producer、条件、目标和 task 全部闭合后才能产生 mutation。
- 波次切换、来源退场、召唤移除和死亡必须保持状态、关系索引、事件及 replay 一致。

## 禁止项

- 按怪物名、技能名、固定 ID、文件名或 AIPath 白名单驱动 runtime。
- 执行 AI 策略、猜测目标或在敌方窗口自动选择动作。
- 把 AI 序列误当作强制战斗规则，或把复杂 AI 简化成固定序列。
- 把 `ModifierList` 当作常驻被动，或把 `AbilityNameList` 当作完整被动系统。
- 目标失败后 fallback 到 actor、主目标、全体或空集合继续结算。
- 在 callback、动态值或召唤关系未准入时产生部分 mutation。
- 用旧 v7、观测结果或描述文本补怪物倍率、目标和行为规则。
