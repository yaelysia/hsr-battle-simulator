  不因代码还能更漂亮或更快而无限延后封版。
- 第 7 项出口满足后停止本版开发。尚有支持范围内的真实阻断时如实未完成；排除内容必须经用户裁决，

## 2. 前因后果

本节保留原 P9 开工背景；以下数量和断点不是当前剩余工作统计，以交接及源码为准。

P1-P8 已建立战斗状态、状态生命周期、伤害、时间线、队列、召唤、数据卡、公式、构筑、
装备和 replay 等底座。当前 79 条目标角色都能生成正式基础战斗单位，但角色完整能力仍有
以下共同断点：

- 共享角色运行时来源没有统一接入角色能力图。
- 17 条记录共有 19 个动作阶段或入口绑定缺口。
- 行迹、星魂的静态贡献和动态能力图尚未通过一条通用构筑绑定链消费。
- 动态值、目标、条件、控制流和事件回调仍只接纳部分真实角色来源形状。
- 状态、伤害、资源、队列、死亡、击破、形态和独立行动实体的底座存在，但角色来源的
  payload、事件生产者和生命周期尚未全部接通。
- 6 个混淆战斗节点族共 110 次出现，另有大黑塔追加攻击分支引用的真实 ability 缺失。

旧盘点中的 blocked 数量混合了表现节点、上游事件准入和下游效果语义。同一状态任务因
多个事件未准入会重复报数，不能按 blocked 总数或角色数估算工程量。P9 按共享根因施工，
每个来源出现只能有一个当前主要责任阶段和必要的下游依赖。

## 3. 目标架构

P9 完成后，角色内容应沿唯一链路进入战斗：

```text
角色主能力 / 共享角色能力 / 行迹 / 星魂
                  |
                  v
      范围分类与来源图 -> Canonical IR
                  |
                  v
       CharacterBuildAssembler
                  |
                  v
  已装配能力引用 + 正式动作定义 + 初始状态
                  |
                  v
 数值/目标/条件/控制流/事件 -> 通用领域系统 -> 原子提交
                  |
                  v
       settlement / source audit / replay
```

角色卡只保存来源组合和动作定义。构筑装配器只解析最终等级、行迹、星魂和机制引用。
runtime 只执行类型化 IR，不读取 raw、角色名、技能名、文本或 source trace 决定规则。

## 4. P9 总目标

本节保留 P9 历史目标；整个工程的范围与结束条件以第 0 节为准。原 79 条非记忆、非欢愉
角色的来源盘点仅作为需求和复用线索，不是本版完整目录，也不代表当前剩余工作量。

保留唯一通用执行器、确定性 RNG、原子提交和来源追溯；移除阶段数量、角色数量、
覆盖率和验证数量对交付优先级的替代。来源缺口与实现缺口分开记录，已有研究先落实。

## 5. P9 明确不做

- 当前通用机制阶段不全面扩充记忆/欢愉专属内容；后续按第 0 节内容路线增量处理。
- 不模拟角色获取、等级材料、晋阶材料、行迹解锁路线、星魂取得和技能升级过程。
- 不实现动画、镜头、音效、VFX、HUD、客户端选目标流程或物理弹道。
- 不实现敌方 AI 或自动战斗。外部推演器像玩家一样查询并选择敌我动作。
- 不按角色名、技能名、固定 ID、固定文件名、文本描述或观测伤害建立 runtime 分支。
- 不重做 P2/P7/P8 已验收底座；只有当前角色真实来源暴露共享缺口时做最小通用扩展。
- 不借 P9 建立全项目 validator registry、持久验证缓存或第二套场景/结算实现。
- 不把真实 source gap 改名为实现完成，也不为通过目录审计伪造 synthetic gameplay 来源。

## 6. 全局架构红线

1. raw TBGD 与已确认研究只经 L0 编译/正式规则声明进入类型化输入；runtime 不直接读取原始来源。
2. 每个 mutation 必须来自真实 IR 节点，并原生生成 settlement、来源审计和 replay。
3. 缺来源、目标、参数、事件上下文或公式时，在提交前 blocked，state、event 和 RNG 不变。
4. 同一效果语义只有一个生产入口；动作、callback、provider 和战斗事件不得复制 handler。
5. 构筑条件在 assembly 解析，事件条件在 typed event context 解析，两者不得混用。
6. 空目标集合、合法无召唤关系和解析失败必须是不同状态。
7. 事件身份由生产者和生命周期定义；同身份不同 payload 或来源必须 fail-closed。
8. 外部推演器只提交内核公布的动作、目标和 RNG 选择，不计算合法性或效果。
9. 固定角色 ID 只允许出现在明确标记的最终示例 manifest，不能进入通用验证选样或生产代码。
10. 当前阶段没有真实生产者但依赖未来新命途/怪物/关卡的机制，只能记录外部内容依赖，
    不能用合成生产者冒充已闭合。

## 10. 验证与资源总策略

- 先确定这次改动有什么实际错误风险，再决定是否需要测试以及测试什么。
- 非平凡机制保留最小可运行行为检查；优先验证真实动作的结果、关键事件顺序与资源变化。
- 不追覆盖率、测试数量或目录全零；内核已自动拒绝的非法输入、无真实调用的畸形场景不重复铺矩阵。
- 只有改动可能破坏状态原子性、RNG 或连续性时，才增加对应失败/回放检查，不按阶段固定附加。
- 通用执行链变更影响现有 MVP 时运行该场景；规则稳定后的独立回放按实际需要运行，不重复整场。
- 文档调整只检查相关链接、旧指令冲突和补丁格式，不跑战斗测试。
- 不重跑无关 P1-P8 聚合或历史验证套餐，不为验证器建设持久缓存、注册框架或第二套规则。
- 能读取窄范围来源就不构建全量 IR；临时产物放 /tmp，避免重复的大型诊断 dump。正式战斗归档
  仍保留必要的状态、事件、随机结果、mutation 和结算，不以减小测试产物为由删除回放事实。
- 只有用户要求对明确目录范围作完整支持声明时，才进行相应目录核对。

## 11. Gap 和完成口径

定位缺口时区分：来源/规则尚未确认、L0 绑定或编译缺失、正式入口未接、L1 语义未实现、
L2 内容未装配，以及已有实现缺少有效行为证据。不能把这些都当成新增机制，更不能把“拒绝
执行”记成机制完成。PR #8 已确认的研究规则不因 raw 缺少同值就归为未知来源。

当前进度描述三件事：机制支持什么正式行为、对应什么可运行证据、还限制哪些内容或分支。
未完成项可以按真实依赖推进或明确延期；已延期不等于已完成。机制阶段使用第 0 节完成条件，
内容阶段对声明的角色/怪物/构筑范围负责，不使用全目录的统一零缺口门槛。

原 `P9-SHARED-MECHANISMS-DONE` 和 `current_79_character_catalog_all_executable` 属于旧总验收
口径，保留在历史记录中，不作为新路线前置，也不通过改名或改勾选宣称其旧范围已经完成。
