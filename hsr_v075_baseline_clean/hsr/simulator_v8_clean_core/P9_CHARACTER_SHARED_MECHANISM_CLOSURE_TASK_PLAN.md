# P9 通用战斗底层与内容扩展路线

2026-09-28 按用户确认的边界修订：先做好通用战斗底层，再逐步接入角色、敌人和场地效果，
在接入具体内容时实现它需要的特殊机制。通用底层比当前单场景 MVP 更完整，但不提前实现
最终模拟器可能需要的全部机制。现有 CLI MVP 持续作为机制验证和游戏实测对照载体。

本文件维护后续路线；当前实际进度与下一步只在 [CODEX_HANDOFF.md](../CODEX_HANDOFF.md)
维护。原 P9 阶段编号、机制分类和已完成记录保留，用于定位与复用，不再作为严格串行审批链。

## 0. 当前路线：机制优先，内容逐步扩充

### 四层架构保持不变

| 层 | 职责 | 职责约束 |
| --- | --- | --- |
| L0 来源编译 | TBGD、已确认研究事实进入编译或正式规则声明，形成类型化 IR / RuleBook 输入 | 保留来源区别；不在 runtime 读取 raw、研究文档或观测日志 |
| L1 通用机制执行 | 目标、事件、状态、数值、资源、行动、生命、击破、召唤、波次与原子提交 | 角色与怪物共用；不按内容名称、固定 ID 写专用执行逻辑 |
| L2 内容装配 | 角色卡、怪物卡、召唤物子卡、光锥、遗器、构筑和关卡组合机制与参数 | 只声明和装配，不自行结算伤害、状态或时间线 |
| L3 外部操作 | CLI、人工操作与外部推演器查询合法选择、提交命令、读取结果 | 不计算规则；本阶段继续使用 CLI，不扩 UI |

source audit、settlement、snapshot 和 replay 横切四层，不新增第五层业务执行器。
详细结构沿用 [架构契约](ARCHITECTURE_BOUNDARY_CONTRACT.md)，不重做 P1-P8。

架构归属与开发顺序分别判断：特殊机制后续仍可能需要扩展 L0/L1，再由 L2 装配；不能因为
某个机制适合复用或最终应放进 L1，就把它提前列为接入内容之前的必做项。

### 事实与实施约定

- PR #8 中用户确认的规则可以直接实现，不要求再找到 TBGD 同值或 native 赋值位置。
  研究结论编译或注册为正式类型化规则，并标注实际研究来源，不能伪称 TBGD 来源。
  这覆盖旧文档中与本授权冲突的来源限制；未确认的猜测、单次观测伤害和旧实现不自动成为规则。
- 以当前源码和本地已完成修改为基线。P9 后续阶段尚未勾选，不代表对应机制全部未实现。
- 优先复用已有系统和正式入口；先分清参数绑定、来源准入、调用缺失和真正的语义缺失，再写代码。
- 第一阶段只处理下述基本规则和通用执行能力；特殊机制由第二阶段的具体内容需求触发。
  为验证底层可以装配少量角色、敌人或场景，样例不引入整套特殊机制的前置施工。
- 对未知规则仅暂停依赖它的分支，继续独立的已确认工作；不得用猜值放行，也不得让局部未知
  阻塞所有通用机制。是否需要补研究必须说明具体行为，不能把实现缺口转交用户重做研究。
- 完全本地实施，不恢复 MCP 任务账本、固定 PLAN/EXEC/REVIEW 审批、逐卡 PR 或推送流程。
  用户另行要求之前不提交、不推送，不更新 TBGD submodule 指针。

### 第一阶段：完成可复用的通用战斗底层

本阶段范围是角色、敌人和场地共同依赖的基本战斗规则与执行能力。已有 P1-P8、P9 及 PR #8
落地成果直接复用，只补实际缺口；旧阶段未勾选不代表需要重写或重新验证整个领域。

| 基础范围 | 当前基础与施工边界 |
| --- | --- |
| 数值、资源与普通生命变化 | 常规伤害、治疗、护盾、属性、战技点、能量、HP 变化与普通死亡已有主体实现；保留 PR #8 修复，只处理这些基本规则的真实缺口。复活和特殊资源不列为前置 |
| 基础状态生命周期 | 添加、移除、叠层、持续时间、属性修正以及已有控制/抵抗/免疫能力继续复用；补基本计时和事件消费的实际断点。某个状态的专属触发与例外规则随内容接入 |
| 行动与时间线 | 复用回合推进、速度、行动提前/延后、队列、合法动作/目标查询及已接通的终结技插入；补基本行动窗口和调度衔接。具体技能触发追加/额外行动的条件及专属顺序随内容接入 |
| 目标、事件与执行链 | 正式动作、状态回调、嵌套能力共用任务图、条件、目标、RNG 和原子提交；接通现有通用执行器的真实调用，不预做全部技能任务形态 |
| 普通弱点、韧性与击破 | 复用弱点判定、削韧、跨零处理和普通击破结算，补自然恢复与状态/调度的连接；具体技能削韧参数随内容绑定，超击破触发与特殊韧性规则随相关内容接入 |
| 基本战斗生命周期 | 复用场景初始化、普通入场/死亡/退场、胜负与结束；保留已有单位和波次底座。具体召唤、敌人阶段脚本、关卡波次出生配置及场地效果在接入对应内容时完成 |

当前已知的底层施工入口：

1. 正式动作/状态回调的 weighted-selection caller 与 RNG 记录已本地接通，复用既有任务图
   执行器；完整投射物/弹射内容仍按对应技能接入，不重开随机算法研究。
2. 基础状态计时只补已有明确行为的调度断点。PR #8 最新修订已标注首次计时研究存在争议并暂停；
   不把 `LifeStepImmediately` 字段直接解释为统一首跳算法，也不预先实现全部特殊状态交互。
3. 普通击破数值、风化层数和已确认恢复规则在原内核补接；完整公共击破链仍需明确
   `TriggerBreak(Caster)` 与已有击破通知的映射，避免重复触发。组件级检查不能替代
   “命中→击破→恢复”的完整链证据，七元素其它触发路线和特殊时序随内容验证。

这些条目用于定位当前已知边界，其中首次计时待研究确认，不是立即施工项；它们不代替上表的
底层范围，也不表示其余领域全部经过重新验证。
发现新问题时按基本规则或具体内容需求归属，不能把旧 P9 的所有未完成项搬进本阶段。

多盾消耗、致死/多请求受击回能属于基本规则的边界问题，不能改名为角色特殊机制来隐藏。
普通多盾并行吸收和非致死逐请求回能已本地接入；致死回能等用户实测，盾 cap/加成争议保留。
已确认的结论可直接修复；尚不明确的行为保留具体支持限制，只阻断依赖它的动作或
内容，不把全部边界归零设为任何内容接入的前置。更不能在未支持时宣称任意战斗都可运行。

### 底层阶段的结束条件

- 上述基本规则通过正式执行链提供给内容装配，能产生正确的状态、事件和结算；CLI/推演器
  只提交操作，不补算规则。只有函数或 IR 定义而没有正式消费者的基础能力仍算缺口。
- 已有可用能力和新增改动的支持边界清楚；复用现有运行证据，只对实际改动与风险做必要检查。
  MVP 保持可运行，按需增加能说明底层行为的最小场景，不追覆盖率或全目录通过。
- 达到这套可复用基础后就进入内容接入。后续某个特殊机制尚未实现，不延长底层阶段；新增
  内容发现底层缺陷时再修共享实现，不要求先预见所有内容的需求。

### 第二阶段：接入角色、敌人和场地，按需实现特殊机制

每次选定具体内容，先复用现有底层完成参数、动作、被动与生命周期装配；遇到现有机制无法
表达的特殊行为，就在这次内容任务中实现它，再用实际战斗和游戏对比修正。内容阶段允许补
L0/L1，不是只向 L2 填数据，也不另建专用战斗执行器。

| 内容带来的需求 | 接入时处理的工作 |
| --- | --- |
| 带超击破的角色或场地 | 复用已有超击破结算器，连接实际触发条件、参数与事件 |
| 带复活、特殊资源或特殊韧性的角色/敌人 | 实现该内容所需的规则和生命周期，不预先穷举所有变体 |
| 形态变化、召唤物、忆灵或特殊行动 | 复用动作集、owner/summoner、队列与单位生命周期底座，补具体创建、触发、切换和行动规则 |
| 敌人阶段与关卡场地效果 | 复用场景、波次和事件底座，接入实际出生/被动、阶段条件及场地规则 |

- 具体技能的削韧量、额外行动触发等来源绑定随所属内容完成；共享执行能力已存在时只做装配。
- 需要新执行能力时，L0 结构化来源与参数，L1 实现可复用执行语义，L2 声明具体组合，L3 仍只
  查询和提交；不按角色名、敌人名或固定 ID 在内核分支，也不为了未来可能复用预建抽象。
- 角色与敌人同等纳入，敌方操作交人工或外部推演器，不实现敌方 AI。光锥与遗器继续复用 P8。
- 多波、虚韧性等此前移出 MVP 的内容仍在最终范围内；它们不自动升级为当前底层阶段的全部
  前置。是否新增共享能力由对应内容的实际需求决定，既有实现保留复用。
- 每批只说明本次内容的可用行为和限制；未知规则只阻断相关分支，不要求重查全部目录，
  不以数据卡数量代替可玩数量。

游戏内对比贯穿两个阶段：固定构筑和操作，按需对比逐段伤害、资源、行动顺序和状态变化；
随机结果需对齐选择或比较可确认的条件结果。replay 证明确定性与连续性，不能替代游戏正确性。
实测差异先定位到来源、装配、规则或时序，再修共享实现，不能硬编码观测答案。

## 1. 使用方式

从交接文档取得当前机制与真实入口，按第 0 节能力范围完成一个最小完整改动。任务说明只需
写清已有事实、剩余行为、涉及层次/消费者和必要检查；复杂共享改动再补足说明，不强制七块卡片。
验证遵守 [本地执行与验证约定](docs/AGENT_WORKFLOW_AND_VALIDATION.md#0-当前本地工作方式)。

旧执行卡集中在 [P9 执行卡索引](docs/p9_execution_cards/README.md)，用于查机制和历史证据，
不能用旧审批、允许写集合或阶段顺序覆盖用户已授权的新路线。遇到真实规则不清或会改变架构、
兼容方向的决定仍询问用户；日常接线与修复无需重复申请批准。

角色范围与机制包归类保留在以下资料中，数量是原 P9 固定来源基线，不是当前游戏或施工分母：

## 2. 前因后果

本节保留原 P9 开工背景；以下数量和断点不是当前剩余工作统计，以交接及源码为准。

P1-P8 已建立战斗状态、状态生命周期、伤害、时间线、队列、召唤、数据卡、公式、构筑、
装备和 replay 等底座。当前 79 条目标角色都能生成正式基础战斗单位，但角色完整能力仍有
以下共同断点：

- 共享角色运行时来源没有统一接入角色能力图。
- 17 条记录共有 19 个动作阶段或入口绑定缺口。
- 行迹、星魂的静态贡献和动态能力图尚未通过一条通用构筑绑定链消费。
- 动态值、目标、条件、控制流和事件回调仍只接纳部分真实角色来源形状。
- 状态、伤害、资源、队列、死亡、击破、形态和独立行动实体的底座存在，但角色来源的
  payload、事件生产者和生命周期尚未全部接通。
- 6 个混淆战斗节点族共 110 次出现，另有大黑塔追加攻击分支引用的真实 ability 缺失。

旧盘点中的 blocked 数量混合了表现节点、上游事件准入和下游效果语义。同一状态任务因
多个事件未准入会重复报数，不能按 blocked 总数或角色数估算工程量。P9 按共享根因施工，
每个来源出现只能有一个当前主要责任阶段和必要的下游依赖。

## 3. 目标架构

P9 完成后，角色内容应沿唯一链路进入战斗：

```text
角色主能力 / 共享角色能力 / 行迹 / 星魂
                  |
                  v
      范围分类与来源图 -> Canonical IR
                  |
                  v
       CharacterBuildAssembler
                  |
                  v
  已装配能力引用 + 正式动作定义 + 初始状态
                  |
                  v
 数值/目标/条件/控制流/事件 -> 通用领域系统 -> 原子提交
                  |
                  v
       settlement / source audit / replay
```

角色卡只保存来源组合和动作定义。构筑装配器只解析最终等级、行迹、星魂和机制引用。
runtime 只执行类型化 IR，不读取 raw、角色名、技能名、文本或 source trace 决定规则。

## 4. P9 总目标

当前目标以第 0 节为准：共享机制通过正式调用链执行，四层保持边界，CLI 持续可运行，
然后用同一套机制逐步扩充角色和怪物。原 79 条非记忆、非欢愉角色的来源盘点作为需求和
复用线索保留，不再以四类内部 gap 全零或全目录角色可玩作为通用机制阶段完成门槛。

保留唯一通用执行器、确定性 RNG、原子提交和来源追溯；移除阶段数量、角色数量、
覆盖率和验证数量对交付优先级的替代。来源缺口与实现缺口分开记录，已有研究先落实。

## 5. P9 明确不做

- 当前通用机制阶段不全面扩充记忆/欢愉专属内容；后续按第 0 节内容路线增量处理。
- 不模拟角色获取、等级材料、晋阶材料、行迹解锁路线、星魂取得和技能升级过程。
- 不实现动画、镜头、音效、VFX、HUD、客户端选目标流程或物理弹道。
- 不实现敌方 AI 或自动战斗。外部推演器像玩家一样查询并选择敌我动作。
- 不按角色名、技能名、固定 ID、固定文件名、文本描述或观测伤害建立 runtime 分支。
- 不重做 P2/P7/P8 已验收底座；只有当前角色真实来源暴露共享缺口时做最小通用扩展。
- 不借 P9 建立全项目 validator registry、持久验证缓存或第二套场景/结算实现。
- 不把真实 source gap 改名为实现完成，也不为通过目录审计伪造 synthetic gameplay 来源。

## 6. 全局架构红线

1. raw TBGD 与已确认研究只经 L0 编译/正式规则声明进入类型化输入；runtime 不直接读取原始来源。
2. 每个 mutation 必须来自真实 IR 节点，并原生生成 settlement、来源审计和 replay。
3. 缺来源、目标、参数、事件上下文或公式时，在提交前 blocked，state、event 和 RNG 不变。
4. 同一效果语义只有一个生产入口；动作、callback、provider 和战斗事件不得复制 handler。
5. 构筑条件在 assembly 解析，事件条件在 typed event context 解析，两者不得混用。
6. 空目标集合、合法无召唤关系和解析失败必须是不同状态。
7. 事件身份由生产者和生命周期定义；同身份不同 payload 或来源必须 fail-closed。
8. 外部推演器只提交内核公布的动作、目标和 RNG 选择，不计算合法性或效果。
9. 固定角色 ID 只允许出现在明确标记的最终示例 manifest，不能进入通用验证选样或生产代码。
10. 当前阶段没有真实生产者但依赖未来新命途/怪物/关卡的机制，只能记录外部内容依赖，
    不能用合成生产者冒充已闭合。

检查点。旧阶段负责说明机制归属；可以一次修复同一根因涉及的来源、准入和正式消费者。

默认下一项为正式动作/状态回调的 weighted-selection caller 与 RNG 接入：复用已完成的
TaskGraphExecutor 契约、目标解析和事务空间，让真实权重、被选分支和 RNGEvent 进入正式结算。
不恢复、不移植失败测试 PR #9；从当前主线加本地实现继续。

无依赖的已确认规则可以独立推进。共享文件修改由主线程协调；经用户允许可给 Sol/Terra
分派边界明确的任务，不并行改同一段，也不为并行建立第二套接口。

## 10. 验证与资源总策略

- 先确定这次改动有什么实际错误风险，再决定是否需要测试以及测试什么。
- 非平凡机制保留最小可运行行为检查；优先验证真实动作的结果、关键事件顺序与资源变化。
- 不追覆盖率、测试数量或目录全零；内核已自动拒绝的非法输入、无真实调用的畸形场景不重复铺矩阵。
- 只有改动可能破坏状态原子性、RNG 或连续性时，才增加对应失败/回放检查，不按阶段固定附加。
- 通用执行链变更影响现有 MVP 时运行该场景；规则稳定后的独立回放按实际需要运行，不重复整场。
- 文档调整只检查相关链接、旧指令冲突和补丁格式，不跑战斗测试。
- 不重跑无关 P1-P8 聚合或历史验证套餐，不为验证器建设持久缓存、注册框架或第二套规则。
- 能读取窄范围来源就不构建全量 IR；临时产物放 /tmp，避免重复的大型诊断 dump。正式战斗归档
  仍保留必要的状态、事件、随机结果、mutation 和结算，不以减小测试产物为由删除回放事实。
- 只有用户要求对明确目录范围作完整支持声明时，才进行相应目录核对。

## 11. Gap 和完成口径

定位缺口时区分：来源/规则尚未确认、L0 绑定或编译缺失、正式入口未接、L1 语义未实现、
L2 内容未装配，以及已有实现缺少有效行为证据。不能把这些都当成新增机制，更不能把“拒绝
执行”记成机制完成。PR #8 已确认的研究规则不因 raw 缺少同值就归为未知来源。

当前进度描述三件事：机制支持什么正式行为、对应什么可运行证据、还限制哪些内容或分支。
未完成项可以按真实依赖推进或明确延期；已延期不等于已完成。机制阶段使用第 0 节完成条件，
内容阶段对声明的角色/怪物/构筑范围负责，不使用全目录的统一零缺口门槛。

原 `P9-SHARED-MECHANISMS-DONE` 和 `current_79_character_catalog_all_executable` 属于旧总验收
口径，保留在历史记录中，不作为新路线前置，也不通过改名或改勾选宣称其旧范围已经完成。
